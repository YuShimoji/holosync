**Parent / Related**: F-04 (docs/specs/ux-refinement-phase1.md), SP-001 (Sync algorithm), SP-005 (Audio master pinning), SP-011 (Playlist queue mode), SP-012 (Channel live monitor)

## 1. 概要と基本方針

### 1.1 背景
HoloSyncの利用において、以下の5つの要望が提起された：
1. **手軽な検索と次動画へのアクセス利便性向上**
2. **動画自体のウィンドウ・ポップアップ対応（複数動画の別窓化）**
3. **普段のYouTube画面からの簡易転送**
4. **ユーザーが制御可能なジャンル・タグ・指向性を持つレコメンド機能**
5. **ライブ配信の予約受信・自動再生・自動同期および関連ストリームのサジェスト**

### 1.2 No-API-Key ファーストの設計思想
従来のYouTube Data API v3（`googleapis.com`）キー入力は、一般ユーザーにとってGoogle Cloud Consoleでのキー発行という高い参入障壁となっていた。また、1日10,000 unitsのクォータ上限や検索APIの制限が存在する。
本仕様では、**「APIキー未設定でも全機能が100%動作する」**ことを基本方針とする。
- 動画再生・同期・音声管理: 既存の **YouTube IFrame Player API** で完結（APIキー不要）。
- 新着・動画情報取得: **YouTube公式公開RSSフィード（Atom 1.0）** を活用（APIキー不要・クォータ制限なし）。
- 推薦・指向性制御: YouTube側のアルゴリズムに依存せず、**アプリ内部（クライアントサイド）のスコアリングエンジン** で処理。
- 検索・探す体験: **普段のブラウザからのURLワンクリック転送** を主軸にし、アプリ内の検索負荷を大幅軽減。
- ※ 既存の `youtubeApiKey` 設定は、上級者向けのオプショナル機能として残存・共存させる。

## 3. 機能仕様詳細

### 3.1 外部ブラウザからの簡易転送 (F1: URL Quick Transfer)
- **カスタムURIスキーム**:
  - `holosync://add?url=<YouTube_URL>&action=<immediate|queue|reserve>&t=<seconds>`
  - OSのプロトコルハンドラー登録 (`app.setAsDefaultProtocolClient('holosync')`)。
- **ローカルHTTPエンドポイント**:
  - `http://127.0.0.1:19876/api/add` に対してJSON POST。
  - ブラウザ拡張機能（Tampermonkeyスクリプト / 専用拡張）やブックマークレットから発行可能。
- **パラメータ仕様**:
  ```json
  {
    "url": "https://www.youtube.com/watch?v=5uZa3-RMFos&t=142s",
    "videoId": "5uZa3-RMFos",
    "startSeconds": 142,
    "action": "queue",
    "targetTileId": null
  }
  ```

### 3.2 公開RSSフィード取得とCORS回避 (F2: Public RSS Integration)
- **対象URL**:
  - チャンネルRSS: `https://www.youtube.com/feeds/videos.xml?channel_id=UC...`
  - 再生リストRSS: `https://www.youtube.com/feeds/videos.xml?playlist_id=PL...`
- **CORS回避**:
  - レンダラーからの直接fetchはブラウザセキュリティ（同一オリジンポリシー）で遮断されるため、ElectronメインプロセスのIPCハンドラ `rss:fetch` 経由でNode.js `fetch` を実行。
- **XMLパース**:
  - レンダラー側で標準 `DOMParser` を使用。
  - 抽出項目: `videoId`, `title`, `description`, `published`, `channelId`, `channelTitle`, `thumbnail`, `views`。
- **チャンネルIDの自動解決**:
  - ユーザーが `@handle` やチャンネルURLを入力した場合、ページのHTMLヘッダーから `meta[itemprop="identifier"]` または canonical link を正規表現抽出して `UC...` を解決。

### 3.3 クライアントサイド・パーソナライズエンジン (F3: Smart Profile Engine)
YouTube公式のRSSは単なる新着順（時系列）であるため、アプリ側で指向性・フィルタリングを適用する。
- **プロファイル（ペルソナ）データ構造**:
  - ユーザーは「大会観戦」「作業BGM」「技術解説」など複数のプロファイルを保存可能。
  - プロファイルごとに独立した関心条件・履歴を保持。
  ```json
  {
    "id": "prof_apex",
    "name": "大会・競技観戦",
    "channels": [
      { "id": "UCxxxx1", "name": "選手A", "weight": 1.5 },
      { "id": "UCxxxx2", "name": "大会公式", "weight": 2.0 }
    ],
    "playlists": [],
    "includeKeywords": ["APEX", "スクリム", "大会", "Custom"],
    "excludeKeywords": ["切り抜き", "shorts", "前夜祭"],
    "strategy": {
      "freshnessWeight": 0.4,
      "keywordWeight": 0.4,
      "historyWeight": 0.2
    }
  }
  ```
- **スコアリングパイプライン**:
  1. **ハード除外**: `excludeKeywords` または除外チャンネルに合致する動画を完全非表示。
  2. **キーワード適合度**: タイトルおよび説明文に含まれる `includeKeywords` の出現頻度・重要度を加算。
  3. **チャンネル優先度**: 登録チャンネルの `weight` に応じて加算。
  4. **新着鮮度減衰 (Freshness Decay)**: 公開からの経過時間に応じてスコアを減衰（直近数時間の投稿を優先）。
  5. **ローカル視聴履歴ブースト**: 当該プロファイル内で実際に再生した動画・チャンネルをスコアに加点。
  6. **選出理由バッジの付与**: カード上に `[登録CH新着]` `[キーワード一致]` `[スコア: 95]` を表示。

### 3.4 検索＆フィードトレイUI (F4: Tray UI / F-04整合)
F-04（右側トレイ案）を基盤とし、動画再生を遮蔽せず右側からオーバーレイ展開。
- **ショートカット**: `Ctrl+F` または `/` でトレイ展開・フォーカス、`Esc` で収納。
- **タブ構成**:
  - `[フィード]`: プロファイル別パーソナライズド候補一覧。
  - `[検索]`: URL直接入力＋履歴サジェスト（APIキーがある場合のみキーワード検索）。
  - `[キュー]`: SP-011準拠の「次に見る（Up Next）」リスト。
- **カード操作アクション (1クリック)**:
  - `[置換]`: フォーカス中（アクティブ）タイルの動画を差し替え。
  - `[追加]`: メインステージの空き領域または末尾に新規タイル配置。
  - `[次]`: キュー末尾へ追加。
  - `[別窓]`: 独立ポップアップウィンドウとして即時起動。

### 3.5 マルチ・ポップアウトウィンドウ (F5: Master-Satellite Windowing)
- **ウィンドウ構成**:
  - メインウィンドウが **Master Renderer** として全体状態（`SyncController`, `AudioMasterController`）を保持。
  - 切り離された動画は独立した **Satellite BrowserWindow** で起動。
  - タイル右上メニューに「ウィンドウ分離（Pop-out）」アイコンを追加。分離時、本体タイルは「[別窓で再生中] [本体に戻す]」のプレースホルダーとなり二重再生を防止。
- **機能**:
  - フレームレス／最前面固定（Always-on-top）トグル。
  - 別モニターへの配置、ウィンドウサイズ・位置（`windowState`）の保持・復元。
  - メインウィンドウの `SyncController` がIPCを通じて定期的に再生時刻・状態を監視・指示し、本体のシーク・一時停止と完全連動。

### 3.6 ライブ予約・自動再生・自動同期 (F6: Multi-Live Reservation)
- **予約登録**:
  - 配信待機枠URL（またはチャンネルID）を予約リストに登録。
  - 主配信（Leader）と副配信（Follower/Companion）を指定。
- **開始検知**:
  - APIキーを使わず、IFrame Player APIの先行待機状態から発火する `onStateChange`（未開始 `UNSTARTED` からバッファリング/再生へ遷移）を検知。
  - またはチャンネルの公開RSSを定期更新し、新着ライブ動画の生成を捕捉。
- **Autoplayポリシー対策**:
  - Web標準の複数動画自動再生制限を回避するため、**主配信のみ音声ON** で再生開始し、**副配信は明示的にミュート（`muted: true`）** で自動再生を開始。
- **関連ストリーム連携**:
  - 主配信のタイトル・説明文からコラボ相手の `@ハンドル` やハッシュタグを抽出し、トレイ内に関連配信候補として提示。

## Phase 1 実装状況（2026-11-04、当時）

Electron の固定 YouTube エンドポイント経由でチャンネル ID・ハンドル・再生リスト ID／URL の RSS を取得し、Atom の動画を右側トレイに表示して追加できる。API キーは不要。入力エラー・取得エラー・空結果を表示し、狭い画面ではトレイ表示中のみ左サイドバーを収納する。

Phase 1 時点ではフィードの基礎であり、プロファイル、候補のパーソナライズ、フィード／検索／キューのタブ統合、置換・次・別窓操作、チャンネル登録の保存は未実装。ブラウザ単体では CORS 回避用の Electron IPC がないため取得できない。ハンドル解決は YouTube の HTML 構造に依存し、失敗時はチャンネル ID を使う。RSS は全動画やライブ状態を保証しない。

## Phase 2 実装状況（2026-11-04）

- 全画面フィードは自動または1〜6列。閉じると再生画面に戻り、取得結果は複数登録元から集約する。
- プロファイルごとに登録元、関心・除外語、除外チャンネル、チャンネル重み、新着重視度、フィードから追加して連続10秒以上再生したチャンネルの履歴をローカル保存する。複数登録元の重複を除き、除外後に新着・関心語・重み・そのプロファイルの履歴で並べる。既存の全体視聴履歴は混ぜない。
- Windows パッケージ起動時に `holosync://` を登録する。`holosync://add?url=<YouTube_URL>&action=immediate&t=<seconds>` は動画を追加し自動再生を要求、`action=queue` は `targetTileId` 指定時はそのタイル、未指定時は音声マスターまたは先頭タイルのキューへ追加する。キューの開始位置指定と `reserve` は受け付けない。自動再生は YouTube とブラウザの制限に左右される。
- 起動中の `127.0.0.1:19876/api/add` は JSON POST を受け付ける。19876 が使用中ならアプリの実ポートに変わる。許可する Origin は YouTube と Origin なしのローカルクライアントのみで、対象動画・操作を検証する。受理 HTTP 202 は画面への配送を示し、再生成功を保証しない。
- 画面の「条件を編集」から転送用ブックマークレットをコピーし、ブラウザのブックマーク URL に登録できる。コピーできない場合の内容: `javascript:location.href='holosync://add?url='+encodeURIComponent(location.href)`。
- 自動再生の実際の可否、ブラウザ上のブックマーク登録から OS 起動までの利用者操作は未確認。別窓、予約、検索／キューのタブ統合は未実装。ハンドル解決と RSS の公開範囲は YouTube に依存する。

## 5. 検証基準 (Acceptance Criteria)

1. **APIキー完全未設定環境での動作**:
   - `youtubeApiKey` が null の状態でも、RSS取得・プロファイル別フィード表示・動画再生が正常に行えること。
2. **CORSおよびXMLパースの健全性**:
   - YouTube公式RSSのAtom XMLをエラーなくパースし、サムネイル・タイトル・動画IDが正しくUIに反映されること。
3. **プロファイル分離**:
   - プロファイルAでの除外・加点条件がプロファイルBのサジェスト結果に影響を与えないこと。
4. **ポップアウト同期**:
   - 別窓化された動画が、本体ウィンドウの「全体一時停止」「全体シーク」に1秒以内で追従すること。
